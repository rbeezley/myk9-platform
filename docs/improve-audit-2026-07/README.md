## How this audit was run (the methodology, so you can repeat it)

Four read-only auditor subagents swept in parallel, each scoped to one risk area
and each pre-loaded with the project's rejected-findings ledger + ADRs so they
would not re-report settled tradeoffs:

1. **App correctness** — registration/cart, secretary workbench, show-map,
   dates/timezones, status-enum maps, React hazards, error states.
2. **Security / RLS** — policies, GRANTs, edge-function auth, XSS sinks.
3. **Offline / replication & concurrency** — the mutation queue, OCC tokens,
   conflict resolution, quota eviction, ringside show-day reliability.
4. **Payments / data integrity** — Stripe webhooks, refunds, entry-status
   transitions, placement recalculation.

Every raw finding was then **vetted by hand** — I opened the cited code and
confirmed it before it earned a row here. Auditors over-report: of ~40 raw
findings, roughly a third were false positives where the code already guards the
case (see "Rejected" at the bottom — recorded so nobody re-audits them). That
vetting step is the point of the process; treat any future automated finding as
a *lead*, not a fact, until the code is read.

**Proof-of-fix convention.** Every fix plan is *assertion-first* (per
`CLAUDE.md` → Testing): write the failing test that pins the wrong behavior,
run it red, then make the fix flip it green. The red→green transition is the
proof — not visual inspection, not typechecking. Each plan's "Test plan" and
"Done criteria" spell out exactly which test file and which assertion.

## Direction / lower-severity items (documented, not planned)

These are real but either low-severity or defense-in-depth. Fix opportunistically;
none blocks a first-club test on its own.

- **LegalPage renders markdown via `dangerouslySetInnerHTML` with a hand-rolled
  regex converter and no sanitization** (`apps/myk9show/src/pages/LegalPage.tsx:61,186`).
  LOW today: the markdown is a *build-time static asset* (`fetch(markdownPath)`
  of a bundled `.md`), not user content — exploiting it means the deploy is
  already compromised. Still worth wrapping the output in the existing
  `DOMPurify` helper (`src/utils/sanitization.tsx`) as defense-in-depth before
  this converter is ever pointed at dynamic content.
- **`upsert_ringside_session` RPC has no brute-force throttle**
  (`supabase/migrations/20260530210555_phase_3_ringside_sessions.sql:264`).
  It is `anon`-executable and validates passcodes, but — unlike the
  `validate-passcode` edge function, which *does* rate-limit — this direct RPC
  path does not. MED: viability depends on passcode entropy. Add attempt
  throttling or route passcode entry exclusively through the rate-limited edge
  function.
- **Judge dashboard time-bucketing falls back to device timezone on the
  timezone-math error path** (`apps/myk9show/src/pages/judgeStatsUtils.ts:84`).
  LOW: only wrong on DST-transition days; add a log + a unit test pinning the
  Chicago/PST spring-forward case.
- **`stripe-refund-show` cross-show intent check omits `deleted_at IS NULL`**
  (`.../stripe-refund-show/index.ts:136`). LOW and fail-*safe*: a soft-deleted
  other-show entry would over-conservatively *block* a refund (manual handling),
  never over-refund. Add `.is('deleted_at', null)` when convenient.

## Findings considered and REJECTED (do not re-audit)

Vetting killed these — the code already handles the case. Recorded so a future
run doesn't resurface them:

- **`stripe-webhook` `handleChargeRefunded` uses `.every()` "wrong"** — false.
  `.every()` is deliberate (skip only when *all* refunds are app-originated;
  mixed charges fall through to the RECONCILE alert). The in-code comment names
  the exact review that settled it. (`stripe-webhook/index.ts:247`)
- **Cart-overflow refund "ignores failed entry lines"** — false. Failed lines
  are pushed into `noServiceLineIds` *and* `lineAmountsById`
  (`stripe-webhook/index.ts:756`), which `decideCartOverflowRefund` already
  refunds.
- **Entry-payment auto-refund "double-refunds on re-delivery"** — mitigated.
  `stripe.refunds.create` uses an `idempotencyKey` of
  `entry-payment-request-auto-refund-<session>-<reason>`
  (`stripe-webhook/index.ts:1386`); Stripe dedupes identical re-deliveries.
- **Cart confirmation email "re-sends on webhook re-delivery"** — false. The
  cart-claim latch (`entry_carts` `active→submitted`,
  `stripe-webhook/index.ts:631`) returns *before* the email call at line 944 on
  any re-delivery.
- **`ringside_update_entry` "skips OCC on empty payload"** — false. The
  `v_allowed_fields IS NULL` branch *does* enforce the version check
  (`20260621171500_ringside_update_entry.sql:162-166`).
- **Quota eviction "deletes dirty rows"** — false. `evictToTarget` filters
  `if (row.isDirty) return false` before evicting
  (`packages/replication/src/core/ReplicatedTableCache.ts:240`); `evictLRU` and
  `evictRetainingFraction` both delegate to it.
- **INSERT 23505 left in failed queue** — already fixed; the auditor confirmed
  the guard is in place (`MutationManager.ts:700`).
