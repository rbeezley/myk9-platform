- Cold uses a fresh browser context with empty HTTP cache and IndexedDB; service workers are blocked. For warm, a separate fresh context loads the same route unthrottled until primary data and the service-worker precache are ready, then a new worker-controlled page is measured under the profile throttle. The priming load is not timed.
- HTTP writes are blocked except token refresh and verified read-only RPCs. Telemetry POSTs receive a local 204 response without reaching staging; Realtime WebSocket connections are blocked. Warm samples require worker-controlled scripts; the report records scripts served by the worker and total local replication database rows after priming. That row count does not prove route-specific offline data is complete.
- Request count is CDP page-target network attempts, excluding browser-cache hits and locally handled requests. JavaScript bytes are encoded network bytes; scripts served by the worker contribute zero. Service-worker installation traffic belongs to the unmeasured priming phase.
- Time-to-usable stops after route-specific primary content remains available for 300 ms. LCP, CLS, and TBT proxy are read after a further 500 ms observation window.
- Resource timing buffer size was 10,000 entries per navigation.
- A route is blocked if primary content is not visible within 60 s after DOM content loads; blocked samples have no measured load time.
- INP requires an interaction and is not reported. LCP is null when Chromium provides no entry.
- Official field targets at the 75th percentile: LCP ≤2.5 s, INP <200 ms, CLS ≤0.1. Lab TBT proxy target: <200 ms. Custom mobile time-to-usable triage targets: ≤3 s fast 4G, ≤5 s slow 4G.

## Initial findings

- 108/238 measured LCP samples exceeded 2.5 s. This lab comparison is a warning signal; formal Core Web Vitals pass/fail requires field data at the 75th percentile.
- 105/202 mobile samples exceeded the custom time-to-usable target for their profile.
- TBT proxy ranged 42–402 ms; the lab target is <200 ms. This sums observed long tasks through 500 ms after readiness.
- Maximum observed JavaScript transfer was 2.11 MB. The largest emitted minified chunk was index-DnwOPlaH.js (3.54 MB). Initial JS delivery and parse are candidates for follow-up profiling, not established root causes.
- The largest entry chunk transferred in 119/119 measured cold attempts, at 1126264–1126264 bytes over the wire. Its transfer is a shared cost across those routes.
- The slowest measured secretary or ringside cold route on slow 4G was /judge/dashboard: 28558 ms median across 2 runs.
- The largest observed network request count was 586 on /shows/dededede-0000-0000-0000-000000000010/entries (slow-4g-mobile, cold); investigate the request mix before assigning a cause.
- Local preview TTFB ranged 1–8 ms; this is not representative of production server response time.
