# Unified check-in sheet and scoresheet

**Date:** 2026-08-23
**Status:** Approved, not yet implemented

## Problem

The paper check-in sheet and scoresheet exist twice, in two unrelated implementations:

| | Reports page | Emergency trial packet |
| --- | --- | --- |
| Code | `CheckInSheet.tsx`, `ScoresheetReport.tsx` | `renderer/buildEmergencyTrialPacketPdf.ts` |
| Technology | React + print CSS | jsPDF |
| Runtime | Browser only | Browser and Deno |

They differ in substance, not just markup. The packet's score page records
`[ ] Q [ ] NQ [ ] EX [ ] ABS`, a time, faults, a place and a note line. The Reports
scoresheet records structured NQ and EX reason checklists, three named fault counters,
`MM/SS/TT` time boxes with per-area rows, and a class header carrying element, level,
section, hides, distractions and up to three area time limits.

The packet's version was built as an emergency fallback. That premise was wrong. Dog shows
are paper-driven: check-in sheets and scoresheets are printed for every trial whether the
app is working or not, and **a judge must retain scoresheets for one year** in case of a
dispute. The document in the packet is therefore not a lesser artifact for a bad day — it is
the same legal record, and it should be the same document.

## Goals

- One implementation of each document, used by both surfaces.
- The scoresheet is fast for a judge to complete: check or circle, never write out.
- Registry-varied vocabulary (option 2 of three considered — see Decisions).
- The packet becomes a bundle of the real documents plus its recovery and certification
  pages, rather than parallel copies of them.

## Non-goals

- Implementing the 13 `PlaceholderReport` registry entries. `ukc-nosework-trial-score-sheet`
  and `asca-scent-detection-score-sheet` remain placeholders.
- Changing the other 33 reports.
- Renaming the shared renderer directory (see Known wart).

## Decisions

### Registry variance: one design, varied details

Considered: (1) one generic design for all registries, (2) one design whose vocabulary comes
from registry config, (3) structurally separate sheets per registry.

**Chose 2.** The existing sheet already pulls `element`, `level`, `section`, `hides`,
`distractions` and up to three area time limits from class data, which indicates the shape is
stable across registries and only the wording changes.

### Renderer: jsPDF is canonical

The packet is generated by a Deno cron with no browser, so the shared renderer cannot be
React. That rules out making the React component canonical and rendering the packet
headlessly — there is no browser server-side and no container runtime in this project.

Considered a shared *content model* consumed by both a React and a jsPDF renderer. Rejected:
it prevents content drift but leaves **layout** duplicated, and layout is where a scoresheet
actually fails — a reason list that wraps off the page, a block that fits six dogs in one
browser and five in another, a page break through a signature line. With a single renderer,
what the judge holds is identical whether it was printed from Reports last week or from the
packet at 6am, because it is the same bytes from the same code.

The dual-runtime plumbing already exists: `renderPacketPdf.ts` is the browser binding, and
`buildEmergencyTrialPacketPdf` takes the jsPDF constructor as an argument because the two
runtimes disagree about the export.

### One sheet, superset of both needs

The sheet carries fields that are only needed when the app is down — notably `Place`.

> **INTENT:** When the app is up, the extra fields are information the judge can ignore. Do
> not split this into "normal" and "emergency" variants, and do not remove the ignorable
> fields as a simplification. One document, printed the same way every time, is the point.

## The documents

### Check-in sheet

The union of both current versions; each had something the other lacked.

| Column | Source |
| --- | --- |
| Gate | both |
| Order | packet only |
| Armband | both |
| Call Name | both |
| Breed | both |
| Reg # | Reports only |
| Handler | both |
| Pull / Move / Note | packet only |

Eight columns at 188mm usable width. `Reg #` and `Pull / Move / Note` need width discipline.

### Scoresheet

Class header, from the Reports version: element, level, section, hides, distractions, judge,
trial number, date, and either one time limit or `Area 1/2/3` when `areaCount > 1`.

Per-dog block, five regions across 188mm:

| Region | Width | Contents |
| --- | --- | --- |
| Identity | ~55mm | armband (large), call name, breed, reg #, handler |
| Result | ~30mm | `[ ] Q  [ ] NQ  [ ] EX  [ ] ABS` and `Place: ____` |
| Faults | ~35mm | Handler Error, Safety Concern, Mild Disruption — **tally counts**, small numeric boxes |
| Reasons | ~45mm | NQ list and EX list, checkboxes, from registry config |
| Time | ~23mm | `MM / SS / TT`, or `A1 / A2 / A3 / Total` rows when multi-area |

Taken from the packet rather than Reports:

- **Explicit `Q / NQ / EX / ABS` result boxes.** Reports has only `Q` and `Absent`, leaving
  NQ and EX inferred from which reason is checked. A judge who circles nothing has recorded
  nothing — ambiguous on paper a year later.
- **`Place: ____`.** Placement is normally computed; if the system is down there must be
  somewhere to write it.

The three fault counters are tallies, so they are numeric boxes rather than the ruled lines
the current Reports sheet uses.

### Pagination

The reason lists set the block height: five items at ~4mm plus a label is ~24mm, so a block
is ~36mm. The multi-area time stack (four rows of ~6mm) fits inside that height rather than
extending it.

- A class's **first** page carries the full header and fits **5** dogs.
- **Continuation** pages carry a compact one-line header and fit **6**.

Expected packet growth: roughly **39 → 55–60 pages** for a trial of the size last generated.
This is the accepted cost of bundling the real documents.

Two rules:

1. **A block never splits across a page.** The chunker works in whole blocks and accepts a
   ragged bottom. Half a reason list is worse than white space.
2. **Continuation pages repeat the armband range and class** in the compact header, so a page
   separated from its stack is still identifiable — this document is retained for a year.

## Registry seam

The renderer carries no `@/` aliases and no app imports, because Deno imports it. The two
callers get registry data from different places: the browser has `@/features/registries`, the
edge function has only the row it read from the database.

**The renderer owns the scoresheet config outright, as plain data:**

```ts
interface ScoresheetRegistryConfig {
  orgTitle: string;                  // "AKC Scent Work"
  resultStates: readonly string[];   // Q / NQ / EX / ABS
  faultCounters: readonly string[];  // tallied
  nqReasons: readonly string[];
  exReasons: readonly string[];
}
```

A table keyed by `registry_id` sits beside it in the same Deno-safe module. This works because
the app already imports from that directory — `apps/myk9show/src/features/emergency-trial-packet/`
holds **re-export shims**, not copies — so one module genuinely serves both runtimes.

This is deliberately unlike the `formatPacketSeconds` precedent, which mirrors a `@myk9/core`
helper and is pinned by a test. Mirroring is right there because the original belongs to core.
Scoresheet vocabulary has no prior home, so it gets exactly one.

`@/features/registries` keeps what it owns — landing style, trial registry, timezone. It does
not gain scoresheet vocabulary, and the renderer does not read from it. A test asserts the
renderer's config table covers every registry id the app recognises, so adding a registry
cannot silently produce a sheet carrying another body's reason list.

**An unknown registry falls back to the generic config rather than throwing.** A packet that
fails to render at 6am because a trial carries an unexpected registry id is worse than a sheet
with generic reason lists. The fallback is logged.

## Reports page integration

`ReportDataSet` is already `pages: ReportPageData[]` of `{ trial, classData, entries }` — the
same per-class grouping the packet builder produces, so the callers converge naturally.

**Registry change, minimal by design.** Rather than making `ReportDefinition` a discriminated
union and churning all 35 entries, add one optional field:

```ts
buildPdf?: (dataset: ReportDataSet, sortOrder: string) => Uint8Array;
```

Two entries gain it; 33 keep `component` untouched. `ReportsPage` branches on its presence.

**Preview keeps its current shape.** Build to a blob, render in an `<iframe>`, and point the
existing Print button (`ReportsPage/index.tsx:200`) at `iframe.contentWindow.print()` instead
of the React DOM path. Download becomes available as a side effect. Object URLs are revoked on
change and unmount.

**New code: an adapter** `toScoresheetModel(dataset, sortOrder)` mapping app DB types onto the
renderer's runtime-neutral types. The edge function keeps its own mapper from its own query.
These stay separate because the *sources* differ; a shared adapter would be a union of two
shapes. Everything downstream of the model is shared, which is where drift risk lives.

**`PrintableReport` chrome is bypassed** on this path — the PDF carries its own header and
footer. Two reports will therefore look different from the other 33 in the preview pane.
Accepted: they are the two that must also exist server-side.

## Files removed

`apps/myk9show/src/components/reports/CheckInSheet.tsx` and
`apps/myk9show/src/components/reports/ScoresheetReport.tsx` are deleted, along with
`CheckInSheet.test.tsx`. Their registry entries keep their ids (`check-in-sheet`,
`scoresheet`) and gain `buildPdf` instead of `component`, so nothing that links to a report
by id breaks.

## Testing

- `CheckInSheet.test.tsx` is replaced; both components are deleted.
- Renderer tests live with the packet's, in
  `apps/myk9show/src/features/emergency-trial-packet/*.test.ts`, per the renderer README.
- **Assertions are on geometry and content, never source text.** Block height, dogs-per-page
  for single and multi-area, that no block straddles a page boundary, that reason lists come
  from the registry config. A source-grep test would certify nothing here.
- A registry-coverage test pins the config table against the app's registry ids.
- Long-value test: jsPDF **has no reflow** — an overlong breed name or reason silently
  overprints. Every new text field uses `fitTextToWidth`, and a test drives deliberately long
  values through the layout.

Mutation checks required before this is called done:

| Mutation | Must fail |
| --- | --- |
| Shrink the block so 6 fit where 5 should | pagination test |
| Swap one registry's reason list for another's | registry config test |
| Remove the no-split rule | page-boundary test |
| Drop `fitTextToWidth` from a field | long-value test |

## Known wart

This puts sport vocabulary in a directory named for the emergency packet, which will read
oddly. Renaming mid-change would churn imports for no benefit today. If the shared surface
grows beyond these two documents, rename it then.

## Open questions

None blocking. Sport coverage beyond scent work is out of scope; the config table's shape
accommodates it when another sport arrives.
