# Core-Object UI Consistency Audit

**Date:** 2026-10-01 · **Method:** read-only code read of `origin/main` (no browser walk; layout and mobile points are marked _verify_) · **Scope:** list pages, detail pages, and create/edit forms for the seven core objects: club, show, trial, class, entry, dog and person. **Excluded:** Edit/Delete placement and delete behavior, already decided in [`plan-crud-standard.md`](../archive/plan-crud-standard.md) (MYK9-914); and the dog page role view (MYK9-912).

**Why:** the target secretary is experienced but older and not very computer literate ([`INTENT.md`](../INTENT.md)). For her, a screen that behaves differently from the last one is a reason to stop and doubt. Where two screens do the same thing differently, one of them is wrong.

Paths are under `apps/myk9show/src/` unless noted.

## Summary: the six themes

1. **Where am I?** The page title, breadcrumb and back-navigation differ on every object.
   - Three lists hide the title, so only a small breadcrumb shows.
   - The club page has no breadcrumb.
   - The dog and person pages use an older breadcrumb made of buttons with about 24px targets.
   - The People list is not built on the shared page frame at all.
2. **Did it save?** Feedback after saving is missing or inconsistent.
   - Five save paths give no confirmation.
   - The others say "updated successfully", "changes saved", "saved" or "added".
   - Failed saves show raw technical error text.
3. **One thing, one name.**
   - "Entry" vs "Registration" vs "Enrollment".
   - "Person" vs "User" vs "Exhibitor" for the same record.
   - "Sex" vs "Gender".
   - "Host Club" vs "Hosting Club".
   - "New" vs "Add" vs "Create".
   - The same trial is labelled three different ways on three pages.
4. **The same control looks and behaves differently.**
   - Five different date pickers, and create and edit use different ones for the same field.
   - View toggles, density controls and export sit in different places.
   - Row menus range from 32px to 44px, against the 44px INTENT rule.
   - Some lists have two search boxes, others have none.
5. **Empty, missing and broken states disagree.**
   - An empty value reads "TBD", "—", "-", "Not set", or the row is hidden.
   - "Not found" can be a silent redirect, a retry button that navigates away, or a link to a route that doesn't exist.
   - Only some lists have an offline state.
6. **Tables expose power-user tools.** Every table shows Columns, Export CSV, Compact density and Reset view. Status chips for the same status use different colors and wording.

### Low

- **Pending labels:** "Saving...", "Processing...", "Creating...", "Adding...". Standard: "Saving..." everywhere.
- **Save button disabled with no reason:** happens in every panel.
- **Tab names:** "Basic" vs "Basic Info"; "Optional details" vs "Advanced" vs "More for this dog".
- **Address and phone:** state is free text in some forms and a select in others; phone numbers are never formatted.
- **Offline wording:** missing in most forms and lists. Use the Dogs list pattern.
- **Loading states:** the Setup tabs have none; the Class page skeleton includes a sidebar the page doesn't have.
- **Keyboard:** Trials cards open on Enter but not Space.
- **Sorting:** no sort note anywhere. `ListResultLine` already supports one.
- **Facts labels:** ALL CAPS vs sentence case. Sentence case is easier to read.
- **"Show Chairman":** the term is gendered. AKC uses it, so this is an owner question.
- **Mobile (_verify_ at 375px):** the club Edit button sits over the cover image; the person hero doesn't wrap.

## Owner questions

1. **Create verb:** "Add ‹Object›" everywhere?
2. **Entry vs Registration:** "Entry" for entering a show everywhere, with "Registration" reserved for a dog's registry record?
3. **Secretary label:** "Secretary", "Show Secretary" or "Trial Secretary"? "Show Chairman" or "Chair"?
4. **Premium vs Experience:** which word on the show edit tab?
5. **Email for a person:** required, or optional everywhere? Mail-in entrants have none.
6. **Table tools:** keep Export, Columns and Density visible, or hide them? (Recommend: Export in the bulk bar, one density control or none, Columns and Reset hidden.)
7. **Default list view:** a rule such as table for lists the secretary manages, cards for exhibitor and public lists?
8. **Back button on tabs:** leave the page, or step back through tabs? (Recommend: leave the page.)
9. **Empty values:** "Not set" for fields the secretary should fill, and hide optional blanks?
10. **Detail page width:** one width (1280px) for every detail page?
11. **Person page hero:** move it onto the calmer shared hero?
12. **Class Management vs the Setup Classes tab:** is the duplication justified, or should they merge?
13. **Save confirmation:** always show a toast, or stay silent when the page visibly updates?
