## Pass 3: Affordance Clarity

> Are check-in actions obvious? Can users tell what's tappable?

| #   | Finding                                                                                                                                                                                                                                                        | Severity | Notes                                                                                                                                                                                                                                                                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1 | The "Check In" button on NextUpCard is excellent — full-width, `bg-emerald-600 text-white`, `min-h-[48px]`, with a LogIn icon. Clearly the primary CTA.                                                                                                        | Pass     | Meets INTENT guardrail: "Every common action completes in 1-2 taps." One tap to check in.                                                                                                                                                                                                                                                                  |
| 3.2 | After check-in, the status changes to a `CheckInStatusBadge` pill in the header row. The badge is tappable (opens `CheckInStatusMenu` dropdown) but its affordance as a tappable element is subtle — it looks like a passive status indicator.                 | Medium   | The badge has `hover:shadow-sm hover:brightness-95` and `cursor-pointer`, but no chevron, underline, or "tap to change" hint. On mobile (primary use case), hover states are invisible. An exhibitor who wants to undo check-in may not realize the badge is interactive.                                                                                  |
| 3.3 | The NextUpCard content area is a button that navigates to class detail (`onNavigate`), but `onNavigate` is not wired in ShowDayPage.tsx — it is passed as `undefined`. The entire card interior and the "Next Up" label are buttons with `onClick={() => onNavigate?.(classData.classId)}` but onNavigate is never passed from the page. These are dead tap targets — an exhibitor tapping the card to see more detail gets no response. Either wire the navigation or remove the buttons. |
| 3.4 | ClassTimelineCard has the same issue — two nested buttons (status indicator + class info) both call `onNavigate`, which is undefined from ShowDayPage.                                                                                                         | High     | Same dead tap targets as 3.3.                                                                                                                                                                                                                                                                                                                              |
| 3.5 | CheckInStatusMenu has proper ARIA menu pattern (arrow keys, Home/End, Escape, Enter/Space) and focus trapping. Touch targets are `min-h-[44px]` per item.                                                                                                      | Pass     | Solid accessibility.                                                                                                                                                                                                                                                                                                                                       |
| 3.6 | The StickyShowBar is a button (`type="button"`) that scrolls back to the hero. Its intent is clear — tapping the bar returns you to the detail view.                                                                                                           | Pass     | Good mobile pattern.                                                                                                                                                                                                                                                                                                                                       |
| 3.7 | EntryRow and ResultRow in the collapsed sections use `ROW_BUTTON_CLASS` with `hover:shadow-md hover:-translate-y-0.5 active:scale-[0.99]` and a ChevronRight icon — clear tappable affordance.                                                                 | Pass     | Chevron right is a strong "navigate" signal.                                                                                                                                                                                                                                                                                                               |

## Pass 5: State Coverage

> What if the user has no shows today? Multiple shows? A show that's finished?

| #    | Finding                                                                                                                                                                                                                                | Severity | Notes                                                                                                                                                                                                                                                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5.1  | **No show today:** Empty state is well-handled — friendly message "No show today", icon, explanation of what the page does, and two action buttons (Find Shows, My Entries). No dead end.                                              | Pass     | Matches INTENT: "No dead ends — every screen has an obvious next step."                                                                                                                                                                                                                                                               |
| 5.2  | **Loading state:** Full-screen spinner with `min-h-[60vh]`. No skeleton or content hint.                                                                                                                                               | Medium   | A spinner is acceptable for brief loads, but the INTENT guardrails say "No surprise animations." | 5.3  | **Error state:** Card with "Unable to load show day info" and Retry button. The `isStale` flag and stale label partially address this, but only when cached data exists. First-load errors with no cache would show an empty hero. |
| 5.4  | **Multiple shows:** Multi-show tabs appear when `activeShows.length > 1`. Tabs have `min-h-[48px]`, proper `role="tablist"` and `role="tab"` with `aria-selected`. | 5.5  | **All classes done:** "All Done!" celebration card with Q count, completed section auto-expands, "Done" badge replaces "Live" badge.                                                                                                   | Pass     | Satisfying end state. The celebration is proportional — not over the top, just a gradient card with stats.                                                                                                                                                                                                                            |
| 5.6  | **Show is today but hasn't started:** Preview state shows "Your show is today!" with class count and "Live progress will appear once the show starts."                                                                                 | Pass     | Sets expectations without creating anxiety.                                                                                                                                                                                                                                                                                           |
| 5.7  | **Show started but no classes in progress:** "Show is starting" message with "Make sure you're checked in!" prompt.                                                                                                                    | Pass     | Actionable guidance during a liminal moment.                                                                                                                                                                                                                                                                                          |
| 5.8  | **Stale data:** Warning label shows "last updated X ago" with a Clock icon and `text-warning-orange`. Only appears when poll fails but cached data exists.                                                                             | Pass     | Quiet status indicator, not an error banner. | 5.9  | **Missing run order:** If `myRunningOrder` is null, `estimatedTimeMinutes` returns null, and the time display is conditionally hidden. > Can an exhibitor arriving at the show ground quickly find their next ring time?

| #   | Finding                                                                                                                                                                                        | Severity | Notes                                                                                                                                                                                                             |

| 6.1 | The StickyShowBar provides instant glanceable info on mobile — class name and estimated time visible at the top of the screen even when scrolled. Tapping scrolls back to the full NextUpCard. | Pass     | Excellent mobile-first pattern. An exhibitor pulling out their phone sees the critical info immediately.                                                                                                          |
| 6.2 | The page title is generic "Show Day" — no show name in the `<h1>`. The show name appears in the hero section below. | 6.3 | Time estimation uses adaptive timing — after 3+ dogs scored, it computes average pace from actual scoring timestamps instead of the 3-minute default. | 6.4 | The estimated time on the StickyShowBar shows `~{minutes}m` but does not update in real-time — it updates every 30 seconds when the `showDayDetails` poll returns.                             | Low      | 30-second staleness is acceptable for time estimates. Single-tap, instant feedback via toast on error only.                                                                          |

## Summary

### Overall Assessment

The Show Day page is well-architected for its purpose. The core information hierarchy (NextUpCard -> Later Today -> Completed) maps directly to an exhibitor's mental model on show day. The StickyShowBar, adaptive time estimates, and notification system demonstrate thoughtful design for the high-stress show-day context. The page broadly delivers on the "This respects my time" intent.

### Findings by Severity

#### High (2)

| #   | Finding                                                                                                             | Recommendation                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.3 | NextUpCard content and "Next Up" label are buttons wired to `onNavigate`, which is never passed — dead tap targets. | Wire `onNavigate` in ShowDayPage to `navigate(\`/classes/\${classId}\`)`, or remove the button wrappers if class detail pages don't exist yet. |
| 3.4 | ClassTimelineCard has the same dead `onNavigate` buttons for both the status indicator and class info area.         | Same fix as 3.3 — wire navigation or remove button wrappers.                                                                                   |

#### Medium (4)

| #   | Finding                                                                                                       | Recommendation                                                                                                                                                     |
| --- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1.2 | Run order position is never displayed despite the data being available.                                       | Show "Run order: #7" or "You're #7 of 22" in the NextUpCard and ClassTimelineCard, derived from `myRunningOrder` and `totalEntries`.                               |
| 1.5 | Ring number disappears from NextUpCard once scoring starts.                                                   | Always show ring number when available, regardless of scoring state. Move it to a persistent position (e.g., alongside the class label or in a dedicated line).    |
| 3.2 | Post-check-in status badge looks like a passive indicator, not a tappable control. No mobile affordance hint. | Add a small chevron-down icon next to the badge label, or add subtle "tap to change" assistive text.                                                               |
| 5.2 | Loading state is a plain spinner with no skeleton or screen reader label.                                     | Replace with a skeleton matching the NextUpCard shape, or at minimum add `aria-label="Loading show day information"` and `role="status"` to the spinner container. |

#### Low (9)

| #       | Finding                                                                 | Recommendation                                                                 |
| ------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 2.5     | "My Entries" section shows non-today entries during an active show day. | Hide or skip the entries query when `isShowDay` is true.                       |
| 2.6     | Stats row is at the bottom of the hero, easy to miss.                   | Move stats summary near the show header for at-a-glance progress.              |
| 4.2-4.3 | Unnecessary data fetches (entries + results) run even on show day.      | Conditionally skip these queries when `isShowDay` is true.                     |
| 5.9     | Missing run order silently omits time estimate with no explanation.     | Show "Run order TBD" placeholder text.                                         |
| 5.10    | Multi-show tabs lack `tabpanel` ARIA linkage.                           | Add `role="tabpanel"` and `aria-labelledby` to the content controlled by tabs. |
| 6.2     | Page title is generic "Show Day" without the show name.                 | Use show name in h1 when available: "Show Day — {showName}".                   |
| 6.7     | Error retry uses full page reload.                                      | Use React Query's `refetch()` instead.                                         |
| 6.8     | No manual refresh mechanism for the active show day view.               | Add pull-to-refresh or a small refresh icon near the stale indicator.          |

### Quick Wins

1. **Wire `onNavigate` prop** (3.3, 3.4) — One line change in ShowDayPage.tsx to pass `onClassNavigate={() => navigate(...)}` to the hero. Fixes two high-severity dead tap targets.
2. **Always show ring number** (1.5) — Move `ringNumber` display outside the `hasScoring` conditional in NextUpCard. Five-minute fix.
3. **Add spinner accessibility** (5.2) — Add `role="status"` and `aria-label` to the loading spinner div. One-minute fix.
4. **Skip unnecessary queries on show day** (4.2, 4.3) — Pass `enabled: !showDayData.isShowDay` to `useEntriesQuery` and `useExhibitorResults`. Reduces show-day network load.
