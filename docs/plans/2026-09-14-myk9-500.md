# MYK9-500 — surface registration and breed before first entry

The registration wizard redesign is merged. Its class gate and inline editor
remain correct. Breed is intentionally scoped to an organization registration,
so it must not be duplicated on the base dog record or Essential fields.
This is a narrow UX repair of an existing flow, without a new OpenSpec surface.

## Implementation

1. On Add Dog's Essential tab, tell exhibitors that a show entry needs a dog
   registration and that breed is recorded there. Link directly to the existing
   Add Registration editor, preserving their in-progress dog form.
2. Hide the prompt after a registration is added. Keep registration optional for
   people creating a dog profile before they are ready to enter a show.
3. Leave the redesigned wizard's class gate and organization-specific breed
   storage unchanged. No second breed field, page, or mutation path.

## Testing

2. Verify the prompt disappears after registration and is absent for staff.
3. Run focused Add Dog tests, app typecheck, touched-file lint, code-quality
