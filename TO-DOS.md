#### ✅ RESOLVED: DATA LOSS: Show Creation Silently Fails & UI Lies "Success" — 2026-04-16

> **Triage:** Phase 2 — secretary golden path (create show flow). **Severity: HIGH — user perceived data loss.** **Resolved 2026-04-16.**

- **Root cause (confirmed):** The `shows_insert` RLS policy (migration 016) only permitted `is_club_admin(club_id) OR is_platform_admin()`. A user with the bare `secretary` role had neither check succeed, so Postgres rejected the INSERT with 42501 ("new row violates row-level security policy"). The reason it _looked_ like success: `ReplicatedShowsTable.createShow()` queued the mutation via `queueMutation('INSERT', …)`, which writes to local IndexedDB with `_syncStatus: 'pending'` and returns immediately. The wizard fired confetti/nav on that local write. When the background `MutationManager` later uploaded the mutation, Supabase returned 0 affected rows (RLS silently rejects without throwing) and the `replication:sync-failed` CustomEvent was dispatched — but no component was listening for it, so the failure vanished into console logs. `wizardStore`'s `persist` middleware + seeded React Query cache made the show appear to survive refreshes until localStorage cleared, at which point the user saw the row was gone.
- **Fix A — RLS policy** ([`supabase/migrations/135_allow_secretary_create_show.sql`](supabase/migrations/135_allow_secretary_create_show.sql)): DROP + CREATE `shows_insert` to include `(SELECT public.is_trial_secretary(club_id))` alongside the existing club-admin and site-admin checks. Modernized to `is_site_admin()` per the canonical convention from migration 124. Applied to Supabase via `npx supabase db push` and verified by an authenticated probe INSERT from the Test Secretary session.
- **Fix C-1 — Wizard verifies server insert** ([`apps/myk9show/src/pages/secretary/ShowCreationWizard/useShowCreationWizardActions.ts:48`](apps/myk9show/src/pages/secretary/ShowCreationWizard/useShowCreationWizardActions.ts#L48)): Replaced fire-and-forget `triggerSync().catch(...)` with `await triggerSync()` + a new `verifyShowCreatedOnServer` helper that re-reads `shows` from Supabase after sync. If the row is missing, it rolls back the optimistic Zustand state, deletes the local replicated row, removes the React Query cache entries, and throws — which aborts the success flow, suppresses the confetti/overlay, and surfaces the error via the generic wizard catch. Extracted as an exported function with DI so it can be unit-tested without rendering the wizard.
- **Fix C-2 — Global sync-failed listener** ([`apps/myk9show/src/providers/ReplicationSyncProvider.tsx:374`](apps/myk9show/src/providers/ReplicationSyncProvider.tsx#L374)): Added a `window.addEventListener('replication:sync-failed', …)` that logs the full detail and surfaces a `notifications.error` toast with the first failing mutation's table/operation/error string. Pure formatting logic extracted as exported `formatSyncFailureToast()` for unit testing. This catches future silent-failure bugs across ALL replicated tables, not just shows.
- **Tests:** `apps/myk9show/src/pages/secretary/ShowCreationWizard/__tests__/verifyShowCreatedOnServer.test.ts` (3 tests: happy path, rollback on missing row, Postgres error surfaced); `apps/myk9show/src/providers/__tests__/ReplicationSyncProvider.test.ts` (4 tests: single mutation with error, pluralization, generic fallback, missing error string). All 9 pass; typecheck clean.
- **Follow-ups (not part of this fix):** (a) **Silent DELETE bug** observed during probe cleanup — direct `.delete().eq('id', …)` on `shows` returned no error but the row persisted (likely intercepted by a soft-delete trigger that expects the RPC `soft_delete_show(p_show_id)` with different param name). Worth spawning a separate task. (b) **Pending-write queue UI** — would let users see unsynced mutations with retry; defer to post-fall. (c) **Audit other `queueMutation` call sites** per the same pattern; the global toast listener mitigates the risk but doesn't eliminate the optimistic-UI gap for non-wizard flows. (d) Cross-reference with `project_scoring_sync_bug.md` — same underlying "silent flush failure" class; the global listener surfaces those too now.
