# Per-show query placeholder audit — 2026-09-24

**Issue:** MYK9-648 (batch 3). **Baseline:** `origin/main` at `368ba2f65`. Static review, not a browser walk.

> **Final status (MYK9-709):** every row below is now **OK**. The verdict tables record the state the
> audit found; see [Final status](#final-status-myk9-709) for how it was closed.

## Why this exists

`apps/myk9show/src/lib/queryClient.ts` sets `placeholderData: previousData => previousData` for every
query. In TanStack Query v5, `previousData` is the last data **of the same observer**. So when a mounted
component's show id changes, the query for the new key reports `status: 'success'`, `isLoading: false`
and the old show's `data` (with `isPlaceholderData: true`) until the new read lands. A freshly mounted
observer has no previous data, so this only bites when **the consumer survives the show change**.

MYK9-648 was that bug on `usePublishInfo`. #2355 / #2362 fixed it
(`placeholderData: () => undefined` plus a `select` mask). The new transition test,
`apps/myk9show/src/features/premium/__tests__/publishInfoShowTransition.test.tsx`, renders the real
header Actions item and Premium List card on the production query defaults and goes red on both when
the override is removed.

## When does a consumer survive a show change?

This decides exposure, so it comes before the table.

| Code      | Consumer lifetime across show A → show B                                                                                                                                                                                                | Survives?                                     |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| **HDR**   | App or header level (`AppHeader` → `HeaderActions` / `CommandPalette` → `useCurrentActions`; `App.tsx`). Outside every route element.                                                                                                   | **Always**                                    |
| **SP**    | Show id comes from a search param or an in-page selector, so the pathname does not change.                                                                                                                                              | **Always**                                    |
| **PT**    | Route page wrapped in `PageTransition`. It renders `<motion.div key={location.pathname}>`, which remounts the page on every pathname change, **except under `prefers-reduced-motion`**, where it returns `<>{children}</>` with no key. | **Only with reduced motion**                  |
| **PT+SR** | As PT, and under `ShowManagementSectionRoute`, which renders `null` while `useShowManageScope` resolves. That unmounts the section whenever B's show row is not already in the show store.                                              | Reduced motion **and** B already in the store |
| **RB**    | At-show pages under `RingsideShowBoundary`, which renders a loading state while B's show query is `isLoading`. Its own placeholder is id-guarded, so B always starts loading and the page unmounts.                                     | No                                            |
| **ST**    | Reads Zustand `selectedShowId` on a page with no in-page writer (`/secretary/settings`).                                                                                                                                                | No path found                                 |
| **K**     | Explicitly keyed per show (for example `ShowDeskToolsSheet` keys on `showId`).                                                                                                                                                          | No                                            |
| **—**     | No non-test consumer found.                                                                                                                                                                                                             | n/a                                           |

Two things follow from this table:

1. `ShowDetailsPage` (`/shows/:id`) is **not keyed** by show id. Its per-show isolation for sighted
   users comes from a page-transition animation key, not from any design decision. Every PT verdict
   below turns into a live leak for a user who has reduced motion turned on. The launch persona in
   `docs/INTENT.md` includes older, novice users, who are the likeliest to have it on.
2. The header surfaces are HDR, so they always leak unless the hook opts out. Both header hooks now
   opt out: `usePublishInfo` with an override and `useShowManageScope` with an `isPlaceholderData` guard.

## Method

- `useQuery` / `useInfiniteQuery` calls in non-test files under `apps/myk9show/src` that mention
  `showId` / `show.id`: 72 files and 125 call sites. The table keeps the ones whose **key includes a
  show id**. Club-, dog-, person- and class-only keys were dropped.
- Consumers were found by grepping `hookName(` in non-test files. Mount lifetime comes from
  `routes/*.tsx`, `PageTransition.tsx` and the mounting component.
- Harm is judged on what the previous show's data would make the UI say or do: **money**, **publish or
  visibility state**, **entries or people**, **URLs**, or **actions keyed on the wrong show's row ids**.
  `DISPLAY-ONLY` means wrong but transient text with no action attached.
- Limitation: a hook whose key uses the show id under another variable name, with no `showId` /
  `show.id` token in the file, could be missed. Packages (`packages/*`) are out of scope.

## Verdicts

- **OK**: overrides or guards the placeholder.
- **WRONG-EXPOSED**: wrong under the new show, and the consumer survives a show change in normal use.
- **WRONG-RM**: wrong, but exposed only with reduced motion (PT or PT+SR).
- **WRONG-LATENT**: wrong, but no exposure path was found (ST or —).
- **DISPLAY-ONLY**: see Method.

## Findings

WRONG and exposed in normal use, not filed here:

1. **Scheduled-email toggles read show A's state on show B**
   (`ScheduledLifecycleEmailsPanel`, `/secretary/messages?showId=`). Changing the show filter keeps the
   panel mounted. B's toggles show A's enabled flags until B's read lands, and a click during that window
   writes `isEnabled` derived from A's state to B. This is the only exposed finding that can **write**.
2. **Email delivery history lists show A's deliveries under show B** (`EmailDeliveryHistory`, same
   page). Display only, but "Load more" on placeholder pages would page B with A's cursor.
3. **Volunteer scheduling shows A's roster under `?showId=B`** (`volunteerQueries.ts`,
   `/secretary/volunteers`). The page has no `PageTransition` and is keyed by nothing, so back/forward
   between two `?showId` values keeps it mounted. Delete and assign would act on A's volunteer ids. The
   path is narrow.

Systemic, exposed only with reduced motion:

4. **Per-show isolation on `/shows/:id/**` depends on a page-transition animation key.** With
   `prefers-reduced-motion`, `PageTransition` drops the key, and every WRONG-RM row above leaks the
   previous show on A → B navigation. The worst of these are the official AKC PDF and submission data,
   results visibility, results-release toggles, and registration class availability. One structural fix
   (key the show route element by id, or stop inheriting the global placeholder for show-scoped keys)
   would close the whole class instead of opting out one hook at a time.

Latent (no exposure path today): the money hooks on `/secretary/settings` (refund-all, wait-list
settings) and the unmounted `ShowFinancialSummary` / `PromoCodesSection` queries. They become exposed
the moment any of them is mounted somewhere that survives a show change.

## Replay needs (not run)

Staging holds published Heartland shows and was not touched. A controlled browser replay of MYK9-648
would need:

- two staging shows the replay owns: **A** published with a known PDF and **B** never published,
  seeded by the replay (not Heartland), with a secretary `e2e-*` account that manages both;
- B's publish-info read held open, either through Playwright `page.route` on the PostgREST
  `shows?select=published_premium_url…&id=eq.<B>` request or through network throttling;
- **two runs**: default motion (the card remounts, so only the header item is at risk) and
  `emulateMedia({ reducedMotion: 'reduce' })` (the card instance survives);
- navigation from A to B without a full reload: a header or command-palette link, or `history.back()`
  after visiting B then A;
- assertions on the Actions item text and on every `href` in the Premium List card, with no publish,
  unpublish or download clicked.

## Final status (MYK9-709)

Closed at the source, not per hook. `lib/queryClient.ts` now builds an `EntityScopedQueryClient`
(`lib/entityScopedPlaceholder.ts`), whose default placeholder keeps the previous data **only when the
previous key and the new key name the same entity ids** (every UUID in the key, at any depth). A new
search term, page or filter flag still keeps the list on screen; a new show, class, trial, dog or
person id does not, and the query reports `isLoading` as on a first mount.

| Rows                                                                       | Final status                                                                                                   |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Guarded (7 rows)                                                           | **OK**, unchanged. Their own overrides and `isPlaceholderData` guards still apply and are now belt and braces. |
| Inherit the global `prev => prev` (all rows, including the three findings) | **OK**. Every key in that table carries the show id as a UUID (directly, nested, or in a filter object).       |
| Findings 1–3 (scheduled emails, delivery history, volunteers)              | **OK**. Pinned by `lib/__tests__/showScopedPlaceholder.sites.test.tsx`: A → B with B's read held open.         |
| Finding 4 (reduced motion on `/shows/:id`)                                 | **OK**. Same test file, `PageTransition` rendered with reduced motion on a `/shows/:id` route.                 |
| Latent rows (settings money hooks, unmounted financial queries)            | **OK**: they inherit the same default, so mounting them somewhere that survives a show change is safe.         |

Mutations: no write path can act on another show's placeholder rows any more, because no consumer
receives another entity's rows. Within one show, a placeholder is the same show's data. Queries that
set their own `placeholderData` are left exactly as written (`entityScopedPlaceholder.test.tsx`).
