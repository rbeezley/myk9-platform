# New-user usability walk: exhibitor and secretary (2026-10-20)

Method: browser only, no code reading. Local dev server at `localhost:5173` on `main` (41e615b5f), built-in Claude browser at 1280x900 and 375x812. Walked as an anonymous visitor, then the demo exhibitor (`exhibitor@myk9t.com`, "Mary"), then the secretary (`secretary@myk9t.com`, "Jordan"). The demo exhibitor carries load-test data (258 dogs, 1,282 entries), which distorts some screens; findings that depend on that are marked.

Severity: **P1** blocks or badly misleads a first-time user; **P2** causes confusion or extra work; **P3** polish.

## Top ten, in order

1. Make the public Find Shows page show the published upcoming shows (1).
2. Fix the enter-animation opacity so pages never sit invisible (2).
3. One constant app header above the eight show templates, and one dark-mode rule for homepage and templates (3).
4. Reconcile exhibitor balance and payment history across dashboard and My Payments (8).
5. Default secretary Entries and Results to All when the attention queue is empty (18).
6. Date, venue and entry count on secretary dashboard cards (17).
7. One vocabulary: Enter / Entry / Entries; no cart (4).
8. Redirect `/sign-in` when already signed in (5).
9. Clean the seeded demo shows and the demo exhibitor account (12).
10. Plain-language status line in the secretary workbench header (19).

Not covered: judge and steward roles, club-admin pages, the premium list builder, actual payment, results entry, and email. No data was changed: the only write was a draft class added and then removed on the demo exhibitor's ASCA entry.
