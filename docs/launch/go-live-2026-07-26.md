## 7. Ops readiness

### Blocked: nightly health has failed 6 consecutive nights

`nightly-health.yml` (schedule `0 6 * * *`) has concluded **failure** on 2026-07-21, 22, 23, 24, 25,
and 26. Failing step: `Run read-only nightly health`, with **6 of 6** route-health specs red across
_every_ role — public, exhibitor, secretary, judge, and both admin variants.

Root cause, traced through the run log:

```
[WebServer] ✘ [ERROR] Failed to resolve entry for package "@myk9/core".
             The package may have incorrect main/module/exports specified in its package.json.
http-err: 500 GET http://127.0.0.1:5173/src/main.tsx
Error: public/landing: page rendered blank   (bodyText length 0, expected > 20)
```

`@myk9/core` resolves via `"main": "./dist/index.js"`, and **`nightly-health.yml` never builds the
shared packages.** It runs `pnpm install --frozen-lockfile`, installs Chromium, then starts the Vite
dev server — with no `dist/`. Vite cannot resolve the entry, `/src/main.tsx` 500s, so _every_ route
renders blank and the whole sweep fails for one reason.

`ci.yml` gets this right: every one of its test jobs has a **"Build shared packages"** step before the
tests. `nightly-health.yml` has no equivalent. This is the same built-`dist` trap already recorded in
CLAUDE.md's LESSONS for app tests and for `tsc` against generated DB types — a third instance, this
time in CI.

The fix is one step in the workflow, before `Run read-only nightly health`:

```bash
pnpm build --filter '@myk9/*'
```

Match whatever selector `ci.yml`'s "Build shared packages" step already uses rather than inventing a
new one. Worth noting the failure mode is _loud but uninformative_ — "6 failed, all roles" reads like
a catastrophic app regression, when the app was never served. Six nights of red were plausibly
dismissed as known flakiness.
