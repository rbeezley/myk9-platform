## Design

### Decision

Use a single private `premium-published` bucket for both existing flat PDFs and new immutable versioned PDFs, plus one public committed-pointer download endpoint. This is a clean prelaunch cutover: do not preserve old-app write/rollback compatibility and do not fall back to legacy publishing when RPCs are missing. Keep legacy flat objects readable through the endpoint when the show row still points at the exact `<show-id>.pdf` object. This preserves retained data, including Darboshea, without leaving the bucket public. Do not delete, overwrite, migrate, or otherwise alter Darboshea's object or show row as part of this change.

Option A (a new private bucket alongside the existing public bucket) retains two write contracts, two buckets, a legacy fallback path, and two publication/download security models. It cannot guarantee committed-only downloads for legacy writes to the existing public bucket. Since there are no real users and old test data is disposable except for the explicitly retained Darboshea data, that operational compatibility does not justify keeping the split architecture. Option B makes one object store and one download authority.

### Publication and download contract

The browser renders and uploads a PDF to the private bucket at `<show-id>/<artifact-uuid>.pdf`, with upsert disabled. Upload is staging only and is never directly downloadable by anon. PostgreSQL's authorized row-locked begin-or-reconcile/commit RPCs own the monotonic attempt version and atomically commit the trusted path, publication metadata, and complete experience snapshot. One database guard protects all publication-owned columns across both INSERT and UPDATE: non-Postgres show creation may use only safe empty defaults (no premium pointer/URL/timestamp, attempt zero, committed version null, experience unpublished with null timestamp/style and `{}` snapshot), and later transitions are RPC-only. There is no service-role exception; migration/behavioral fixture setup runs as the database owner. Audit current writers and ensure the generic replicated-show update path cannot submit these fields; the publication RPC is the only application writer. Failed or stale commits leave the previous show row and downloadable premium unchanged.

All callers use one `runPremiumPublishOperation` coordinator. It synchronously installs one active operation per show before any await. Repeated calls with the same mode and intent key receive that promise; an incompatible call for the same show receives a typed conflict, while another show runs independently. This includes both generated card/header publishing and the existing editor's authored unsaved draft; the editor stays because deleting it would discard content that has not been stored elsewhere. On a generated retry, the client first presents the exact prior version/path to the server. If it is the current committed pointer, the server returns success before the LLM runs again. If it is not committed, the server reserves a fresh version and the client regenerates current source data. A staged artifact is reused only when mode, intent key, full content, and signed-in publisher match. A changed draft skips reconciliation and gets a fresh artifact; an exact draft retry can reconcile the previous commit. Row locking serializes browser tabs, and a later reservation makes earlier commits stale. The SQL same-version retry remains idempotent for a duplicate commit request.

The download Edge Function accepts a show ID and resolves the current committed path server-side. Anonymous access requires the same visibility predicate as `public.shows` SELECT (`deleted_at IS NULL` and status in `published`, `upcoming`, `in_progress`, or `completed`). An authenticated show manager also retains the existing management-card preview behavior for a committed draft show: validate the bearer token, then check `can_manage_show(show_id)` or `is_show_secretary(show_id)` using a user-scoped Supabase client/JWT (the helpers include platform-admin access); do not duplicate role joins in Edge code. Only after either the anonymous-public gate or authenticated-manager gate passes may the service-role client sign the exact committed path. A draft is 404/no-sign for anon and 404/no-sign for an authenticated non-manager. Soft-deleted rows remain unavailable. It supports a legacy flat `<show-id>.pdf` path only when the row's committed URL is the exact previously allowed premium URL and the object exists. It never accepts an arbitrary object path from the caller or signs an unreferenced/staged object. The invariant is no anonymous access before commit and resolution of the current DB pointer on each new endpoint request. A signed URL already issued for a previously committed object remains usable until its expiry; changing the pointer is not immediate revocation. Supabase documents signed URLs remain valid until expiry and revocation requires contacting support ([Serving assets from Storage](https://supabase.com/docs/guides/storage/serving/downloads)). Use a short explicit TTL, mint links only on explicit Download actions, and do not persist a public or signed URL as publication authority.

The publish coordinator must not cache a missing-schema result across attempts. A structured missing-RPC error may produce a clear temporary-unavailable message, but never invokes the legacy writer. A later retry rechecks the current API and can proceed after deployment. Remove `legacySchemaByShowId` entirely. The metadata query reports durable publication state independently from download signing; signing errors/404s cannot hide committed status or disable republishing. Mint a fresh signed URL only from an explicit Download click, not as background query data, so a tab cannot continue advertising an expired link.

Before migration, the Edge Function and client metadata reader recognize exact missing-column errors for `published_premium_path` returned as PostgREST `PGRST204` or PostgreSQL `42703`, and then read only the legacy `published_premium_url`. All other errors propagate; this preserves retained legacy/Darboshea reads without hiding outages.

### Deployment and retained data

1. After final code review and required PR CI are green, obtain separate approval to deploy the backward-compatible download Edge Function from the reviewed PR head. Verify reads of existing committed flat PDFs, anonymous denial for drafts, and authenticated authorized-manager preview of a committed draft before merge.
2. Merge the reviewed PR. Vercel auto-deploys the frontend immediately on merge, before CI finishes. Before migration, the new frontend reads old flat committed pointers through the deployed endpoint; missing publication RPCs produce a retryable setup error and no legacy write. Existing old clients and direct public links continue to work because the bucket remains public until migration.
3. Obtain separate explicit linked-database approval, then apply the migration. It adds publication columns/RPCs, switches the existing bucket to private, enforces PDF/size limits, and replaces legacy write policies with scoped immutable staging. From this point, direct public links and old-client writes no longer work; the endpoint serves retained flat objects through signed URLs. Preserve object rows/bytes; specifically do not touch Darboshea.
4. Verify a fresh publish, direct anonymous denial for staged objects, public endpoint delivery for the committed pointer, Darboshea's unchanged row/object and successful endpoint read, and a green production build on a main commit at or after merge. Do not mark MYK9-694 Done until these are evidenced.

The new frontend is deployed by Vercel at merge, before the database migration; until migration, it reads through the endpoint and safely reports publication unavailable rather than writing through a legacy path. Old clients and direct public URLs retain existing behavior during this interval, including the residual risk that a legacy upload can be fetched before its row commits. The strict no-precommit-download guarantee starts only after the approved migration privatizes the bucket; after that cutover, old direct links and old-client writes stop working. The project is prelaunch with no real users; deploy and verify the endpoint before merge and apply the approved migration promptly after merge. Retained data remains intact. Recovery after cutover is a forward fix, not redeployment of the old client.

### Verification contract

- Client tests: upload uses a unique immutable path; no public URL is issued for staged bytes; missing RPC does not invoke legacy upload; the next invocation retries RPC; same-intent retry is idempotent, changed intent conflicts, and stale attempts preserve prior state. Readiness/status remains available during download-signing failure, and each explicit Download click obtains a fresh URL without persisting it. Draft publication continues to offer authorized manager preview.
- Edge Function tests: committed public versioned path gets a short-lived signed URL; exact committed legacy flat path remains readable; authorized show managers can preview a committed draft; anonymous draft and authenticated non-manager draft requests sign nothing; soft-deleted shows always deny; unknown show, null pointer, mismatched/forged path, missing object, and uncommitted artifact return no URL; caller cannot select another show's object. Pre-migration fallback covers both `PGRST204` and `42703`; unrelated errors never fall back.
- Behavioral SQL: manager/club-scoped secretary permissions, stranger/anon denial, exact path validation, PDF/size metadata, atomic failure preservation, stale version rejection, append-only versioned object policy, safe-default authenticated show insertion and denial of prefilled publication state, direct authenticated update denial for every publication-owned show column (including experience snapshot/style/is-published and version counters), and unchanged legacy row/path compatibility for existing reads. Fix the test fixture cleanup by arranging teardown without authenticated `DELETE FROM storage.objects`; do not weaken object immutability or storage protection triggers.
- Integration/deployment check: prove anon cannot GET a staged object directly, endpoint signs only the current committed pointer, previous committed PDF remains downloadable after a failed republish, and Darboshea's existing object and row are unchanged.

### Risks and safeguards

- A signed URL is a bearer credential until expiry; keep expiry short, don't log it, and avoid persistence/caching beyond the request.
- Public download remains intentional for published show premiums; the endpoint only makes the database-committed pointer public.
- `SECURITY DEFINER` RPC/function code must use a fixed search path, explicit authorization, minimal grants, and narrowly scoped service-role access. Draft preview must validate manager access using existing authorization helpers under the caller JWT before service-role signing; never reproduce role-table joins in the Edge Function.
- Private-bucket activation and frontend rollout are not atomic. The project has no real users; order endpoint, migration, frontend and verify promptly.
- Storage cleanup remains separate privileged maintenance. Publication credentials never update/delete staged or committed versioned objects.
