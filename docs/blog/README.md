# Blog / Customer Education

Content calendar and article system for customer education posts. These are external-facing — they build trust, reduce repeated explanations, and help clubs evaluate the platform.

**Platform:** Same static docs site as the knowledge base (`help.myk9show.com` at launch). Blog posts live alongside KB articles — same repo, same PR flow, same staleness checks.

## When a KB Article Becomes a Blog Post

A KB article answers one question, short. A blog post is warranted when:
- There is broader context that helps the user understand the workflow, not just execute a step
- It is a launch announcement or significant workflow change
- The target audience needs trust-building ("is this platform reliable?") not just instruction
- The article would reduce repeated explanation over a longer time horizon than a single support interaction

Blog posts link to KB articles and user-guide sections — they don't duplicate steps.

---

## Tone

Educational, reassuring, practical, never salesy or overpromising. Use dog-show terminology the reader already knows. Avoid software jargon. Write as if explaining to a volunteer secretary in a parking lot before a show.
